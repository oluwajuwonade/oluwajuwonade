# Portfolio Architecture

## Primary positioning

**Data & Quantitative Analyst**

Supporting scope:
**Business Analytics · BI / SQL · Quantitative Analysis · Financial Analytics · Economics / Research**

Specialization:
**AI Evaluation & Research Operations**

The portfolio is organized around the ability to move from a business question to validated evidence and a defensible recommendation.

## Presentation layers

### 01. Flagship case study
The AI-Powered Retail Sales Diagnostic is the dominant portfolio example. It presents:
- the decision question
- executive diagnosis
- quantified evidence
- dashboard artifact
- analytical workflow
- decision implications
- limitations
- three-step evidence path into report/code

### 02. Browser-first case studies
Major projects have case-study pages so recruiters and clients can understand the problem, evidence, method, and limits before opening a repository.

### 03. Technical appendix
GitHub repositories provide source code, data-generation logic, tests, outputs, SQL, and reproducibility evidence.

### 04. BI / SQL proof
The retail diagnostic includes a SQL analytical layer and Power BI-ready model specification. The site labels the static dashboard artifact honestly and does not claim a published Power BI Service deployment.

### 05. Applied public-data proof
A Nigeria Development Data Monitor uses official World Bank indicators to demonstrate applied sourcing and economics-oriented analysis outside synthetic datasets.

### 06. CV
Primary professional identity: **Data & Quantitative Analyst**. AI evaluation is a specialization, not a competing identity.

## Evidence standard

Claims should be proportional to the evidence:
- synthetic = method demonstration
- public data = sourced applied evidence
- client impact = only claimed when directly evidenced

Operating principle:

**Frame → Inspect → Validate → Analyse → Explain → Recommend → Document**
